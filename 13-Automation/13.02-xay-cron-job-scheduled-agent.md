# Xây dựng Cron Job / Scheduled Agent

## Mục tiêu
Thiết lập 1 tác vụ Claude Code chạy tự động theo lịch cố định (Task Scheduler/cron) để thực hiện 1 công việc định kỳ — báo cáo sáng, kiểm tra dữ liệu, tổng hợp thông tin — mà không cần bạn tự kích hoạt mỗi lần, tiết kiệm 10-30 phút mỗi ngày.

## Khi nào dùng
- Đã có 1 script/lệnh Claude Code chạy tốt và ổn định qua nhiều lần thử tay (thường đi sau workflow 13.01)
- Cần 1 báo cáo hoặc bước kiểm tra định kỳ mà bản thân hay quên tự làm
- Muốn tách hẳn 1 việc lặp lại ra khỏi checklist hàng ngày của mình
- KHÔNG dùng cho việc cần con người duyệt/quyết định trước khi thực hiện (gửi email cho khách, hành động tài chính) — trừ khi job có bước dừng lại chờ xác nhận rõ ràng, không chạy tự động hoàn toàn

## Input
- Script/lệnh Claude Code đã test ổn định thủ công ít nhất vài lần
- Lịch chạy mong muốn: giờ, tần suất (hàng ngày, hàng tuần, theo giờ cụ thể)
- Nơi lưu output: file, log, hoặc kênh thông báo (email, Slack...)
- Cách xử lý khi job lỗi: có retry không, có cần được thông báo khi fail không

## Prompt Template
```
Bạn là kỹ sư giúp tôi đóng gói 1 script Claude Code đã chạy ổn định thành 1 scheduled task chạy tự động trên Windows. Tôi tự chạy máy cá nhân, không có server riêng.

Bối cảnh:
- Script/lệnh hiện tại tôi đang chạy tay: {{đường dẫn script hoặc lệnh claude -p "..."}}
- Lịch mong muốn: {{vd: mỗi ngày 7h sáng, mỗi thứ Hai 8h}}
- Output cần lưu ở đâu: {{vd: file .md trong thư mục reports/, gửi email, ghi log}}
- Cách xử lý khi lỗi: {{vd: log lỗi ra file riêng, không cần retry tự động}}

Yêu cầu:
1. Viết 1 script wrapper (.ps1 hoặc .bat) gọi đúng lệnh Claude Code/script chính, có log timestamp mỗi lần chạy.
2. Hướng dẫn từng bước đăng ký scheduled task bằng Task Scheduler (hoặc lệnh schtasks) đúng lịch tôi yêu cầu.
3. Thêm cơ chế phát hiện lỗi: nếu script chạy fail, ghi rõ vào file log riêng (không để im lặng).
4. Giải thích cách tôi kiểm tra job có chạy đúng giờ hay không, và cách huỷ/sửa lịch sau này.

Định dạng output: script wrapper đầy đủ + các bước Task Scheduler dạng danh sách đánh số.
```

## Checklist
- [ ] Đã chạy tay script này thành công ít nhất 3 lần trước khi đưa vào lịch tự động
- [ ] Đã cấu hình log ra file để kiểm tra lại sau, không dựa vào việc tự nhớ đã chạy hay chưa
- [ ] Đã giới hạn quyền của script (không cho phép xoá/gửi ngoài phạm vi cần thiết mà không kiểm soát)
- [ ] Đã tính đến trường hợp máy tắt/ngủ đúng giờ chạy — biết job sẽ bỏ lỡ hay tự chạy bù
- [ ] Đã có cách nhận biết khi job fail (log, thông báo) thay vì phát hiện muộn nhiều ngày sau

## Expected Output
1 scheduled task chạy đúng giờ đã đặt, có log rõ ràng cho mỗi lần chạy (thành công hay thất bại), và 1 cơ chế để bạn biết ngay khi job fail thay vì phải tự kiểm tra thủ công mỗi ngày.

## Common mistakes
- Đưa 1 script chưa test kỹ vào lịch chạy tự động rồi để nó chạy "vô hình" — lỗi âm thầm có thể kéo dài cả tuần mới bị phát hiện
- Cấp cho scheduled agent quyền ghi/xoá quá rộng thay vì giới hạn đúng phạm vi thư mục cần thiết
- Quên xử lý trường hợp máy tắt hoặc ở chế độ sleep vào đúng giờ chạy trên Windows, khiến job âm thầm không chạy
- Không log timestamp và kết quả từng lần chạy, nên không có cách nào biết job có thực sự chạy hay không
- Đặt lịch chạy quá dày (mỗi vài phút) cho việc không cần thiết mức đó, gây tốn chi phí API không đáng

## Phiên bản Claude Code
Trên Windows, cách phổ biến nhất là dùng Task Scheduler gọi 1 script wrapper (`.ps1` hoặc `.bat`) thực thi `claude -p "..."` (chế độ non-interactive) hoặc gọi trực tiếp script Python/Node có dùng Claude API. Cấu trúc gợi ý:
```
scheduled-agent/
  run.ps1              # gọi claude code / script chính, ghi log
  logs/
    run-2026-08-05.log
```
Đăng ký task bằng `schtasks /create /sc daily /st 07:00 /tn "MorningReport" /tr "powershell -File run.ps1"` hoặc qua giao diện Task Scheduler. Nếu môi trường có sẵn plugin quản lý scheduled task (`mcp__scheduled-tasks`), có thể dùng trực tiếp qua Claude thay vì tự cấu hình Task Scheduler thủ công — nhưng luôn review kỹ nội dung job và giới hạn quyền trước khi để nó chạy không giám sát, đặc biệt với các job có khả năng gửi thông tin ra ngoài hoặc ghi đè dữ liệu.

## Khi nào nên dùng Deep Research
Hiếm cần trực tiếp cho việc dựng hạ tầng lịch chạy — đây thuần là việc kỹ thuật cấu hình dựa trên tài liệu Task Scheduler/cron đã có sẵn, rõ ràng. Tuy nhiên tách biệt rõ: nếu nội dung bên trong job (những gì Claude thực sự làm mỗi lần chạy, ví dụ tổng hợp tin tức thị trường mỗi sáng) cần dữ liệu cập nhật và tổng hợp nhiều nguồn, phần đó có thể cần Deep Research — còn bản thân việc "chạy đúng giờ" thì không.

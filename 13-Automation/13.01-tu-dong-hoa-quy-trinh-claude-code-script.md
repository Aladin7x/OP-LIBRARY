# Tự động hoá quy trình lặp lại với Claude Code + Script

## Mục tiêu
Biến 1 quy trình thủ công đang lặp lại (đổi tên/sắp xếp file, tổng hợp báo cáo từ nhiều nguồn, xử lý hàng loạt dữ liệu...) thành 1 script chạy được bằng 1 lệnh, giảm thời gian thực hiện từ nhiều phút mỗi lần xuống còn vài giây, viết xong trong 1 buổi làm việc.

## Khi nào dùng
- Bạn đang làm 1 việc thủ công theo đúng 1 pattern từ 3 lần trở lên
- Quy trình đó mô tả được rõ ràng bằng các bước cụ thể, không cần phán đoán sáng tạo khác nhau mỗi lần
- Bạn đã làm đủ số lần thủ công để biết chắc quy trình này ổn định, không còn thay đổi liên tục
- KHÔNG dùng khi task đòi hỏi tư duy/sáng tạo khác nhau mỗi lần (viết content, ra quyết định kinh doanh) — lúc đó vẫn nên làm qua Claude Chat từng lần

## Input
- Mô tả quy trình hiện tại theo từng bước, đúng như bạn đang làm tay
- Ít nhất 2-3 file/dữ liệu mẫu đầu vào thật và kết quả đầu ra mong muốn tương ứng
- Ngôn ngữ script muốn dùng (Python, Node, PowerShell/Bash) — nếu không chắc, để Claude Code đề xuất dựa trên việc cần làm
- Tần suất dự kiến sẽ chạy script này (vài lần/tuần, hàng ngày...)

## Prompt Template
```
Bạn là kỹ sư tự động hoá giúp tôi viết 1 script thay thế quy trình thủ công sau. Tôi là người tự làm mọi việc, cần script đơn giản, dễ bảo trì, không cần kiến trúc phức tạp.

Quy trình hiện tại tôi đang làm tay, từng bước:
{{mô tả từng bước, càng cụ thể càng tốt}}

Dữ liệu mẫu:
- Input mẫu: {{mô tả hoặc dán ví dụ file/dữ liệu đầu vào thật}}
- Output mong muốn tương ứng: {{mô tả hoặc dán ví dụ kết quả đầu ra thật}}

Ràng buộc:
- Ngôn ngữ: {{Python/Node/PowerShell, hoặc "bạn đề xuất"}}
- Tần suất chạy dự kiến: {{vd: 2-3 lần/tuần, thủ công gọi lệnh}}
- Môi trường chạy: {{Windows/macOS/Linux, có sẵn thư viện gì không}}

Yêu cầu:
1. Viết script chạy được bằng 1 lệnh CLI duy nhất.
2. Xử lý ít nhất 2 edge case hợp lý (file thiếu, định dạng sai, dữ liệu rỗng) — nêu rõ bạn đã xử lý case nào.
3. Thêm log/print đủ để tôi biết script đang làm gì khi chạy.
4. Viết 3-5 dòng hướng dẫn chạy ở cuối, giải thích như cho người không nhớ code sau 1 tháng.

Không tự ý thêm tính năng ngoài yêu cầu — giữ script đơn giản nhất có thể để làm đúng việc cần làm.
```

## Checklist
- [ ] Đã liệt kê input/output mẫu bằng dữ liệu thật, không phải mô tả chung chung
- [ ] Đã tự chạy thử script trên ít nhất 3 case thực tế khác nhau, không chỉ case demo
- [ ] Script có xử lý lỗi cơ bản (file thiếu, định dạng sai) thay vì crash im lặng
- [ ] Đã viết README/comment ngắn để tự nhớ lại cách dùng sau 1 tháng không đụng tới
- [ ] Đã đưa script vào version control (git) nếu đây là script quan trọng, dùng lâu dài

## Expected Output
1 script chạy được bằng 1 lệnh CLI, có log rõ ràng từng bước, xử lý được các edge case cơ bản đã liệt kê, kèm 3-5 dòng hướng dẫn chạy. Không cần tổng quát hoá cho mọi trường hợp có thể xảy ra trong tương lai — chỉ cần đúng và ổn định cho quy trình thật bạn đang thay thế.

## Common mistakes
- Tự động hoá quá sớm khi quy trình còn đang thay đổi liên tục — tốn công viết script rồi phải sửa lại ngay tuần sau, phí hơn cả làm tay
- Không test script với dữ liệu edge case (file rỗng, ký tự đặc biệt, tên file có dấu cách) — lỗi âm thầm chỉ lộ ra khi gặp dữ liệu thật khác mẫu
- Để Claude Code chạy lệnh ghi đè/xoá file mà không review trước — mất dữ liệu gốc không khôi phục được
- Viết script quá "thông minh", over-engineer cho việc chỉ cần chạy vài lần một tháng — tốn thời gian viết hơn thời gian tiết kiệm được
- Không lưu script ở nơi dễ tìm lại, 2 tháng sau quên mất đã có sẵn và làm lại từ đầu

## Phiên bản Claude Code
Đây chính là trọng tâm của workflow này — Claude Code CLI là công cụ chính, không phải Claude Chat. Cấu trúc project gợi ý:
```
automation-project/
  CLAUDE.md          # mô tả quy trình + quy ước dự án
  scripts/
    process.py
  input/
  output/
  README.md
```
Cách chạy: `cd` vào thư mục project, gõ `claude`, mô tả yêu cầu theo prompt template ở trên, review code Claude Code viết ra trước khi cho chạy thật, sau đó test bằng `python scripts/process.py input/ output/`. Nếu quy trình này sẽ lặp lại thường xuyên trong nhiều session sau, cân nhắc tạo 1 custom slash command hoặc skill riêng trong `.claude/skills/` để không phải mô tả lại từ đầu mỗi lần.

## Khi nào nên dùng Deep Research
Hiếm khi cần — phần lớn quyết định nằm ở logic quy trình bạn đã tự biết rõ (vì bạn là người đang làm tay việc đó), không cần tổng hợp thông tin bên ngoài. Ngoại lệ: nếu automation cần tích hợp với 1 thư viện hoặc API bạn chưa quen, dùng 1 lượt research nhanh (không nhất thiết phải Deep Research đầy đủ) để hiểu cách dùng API/thư viện đó trước khi để Claude Code viết script dựa trên thông tin sai hoặc lỗi thời.

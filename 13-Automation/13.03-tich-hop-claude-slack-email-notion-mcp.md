# Tích hợp Claude vào Slack/Email/Notion (MCP)

## Mục tiêu
Kết nối Claude Code với 1 công cụ đang dùng hàng ngày (Slack, Email, Notion) qua MCP để giảm số lần copy-paste thủ công giữa các app, hoàn thành việc setup trong 1 buổi làm việc.

## Khi nào dùng
- Đang copy-paste thủ công giữa Claude và Slack/Notion/Email nhiều lần trong ngày cho cùng 1 loại việc
- Muốn Claude đọc/ghi trực tiếp vào nơi lưu trữ thông tin chính của bạn (Notion database, hộp thư) thay vì qua trung gian
- Có 1 use case cụ thể, lặp lại đủ thường xuyên để việc setup đáng công
- KHÔNG dùng khi tích hợp chỉ để "cho có" — nếu tần suất dùng dưới 1 lần/tuần, copy-paste thủ công vẫn nhanh hơn công sức setup và bảo trì

## Input
- Danh sách công cụ muốn kết nối (Slack, Gmail, Notion...)
- Loại quyền truy cập cần cấp (API key/OAuth) và mức quyền hạn chấp nhận được — đọc (read-only) hay đọc-ghi (read-write)
- Use case cụ thể muốn tự động hoá, mô tả bằng 1 câu rõ ràng (vd: "tóm tắt Slack channel X mỗi sáng", "tạo task Notion từ email gắn nhãn quan trọng")

## Prompt Template
```
Bạn là kỹ sư giúp tôi lên kế hoạch tích hợp Claude Code với {{Slack/Gmail/Notion}} qua MCP, trước khi tôi thao tác cấp quyền thật.

Bối cảnh:
- Công cụ muốn kết nối: {{tên công cụ}}
- Use case cụ thể: {{mô tả 1 câu rõ ràng, vd: "mỗi sáng tóm tắt tin nhắn chưa đọc trong channel #ops"}}
- Mức quyền tôi chấp nhận cấp: {{read-only hay read-write, phạm vi cụ thể — 1 channel, 1 workspace, 1 database...}}
- Tần suất dùng dự kiến: {{vd: hàng ngày, vài lần/tuần}}

Yêu cầu:
1. Xác nhận use case này có thực sự cần tích hợp MCP hay copy-paste thủ công vẫn đủ nhanh — nói thẳng nếu không đáng công setup.
2. Liệt kê các bước cấu hình MCP server cho công cụ này (không thực hiện thật, chỉ lên kế hoạch).
3. Đề xuất phạm vi quyền tối thiểu cần thiết cho đúng use case, không xin quyền rộng hơn cần thiết.
4. Chỉ ra những hành động nào (nếu có) tuyệt đối cần con người xác nhận trước khi Claude thực hiện thật (gửi tin nhắn, tạo/sửa nội dung), không để tự động hoàn toàn.

Định dạng output: danh sách các bước đánh số, có phần "quyền tối thiểu cần cấp" và phần "hành động cần xác nhận thủ công" tách riêng rõ ràng.
```

## Checklist
- [ ] Đã xác định rõ use case cụ thể trước khi setup, không tích hợp lan man "để dùng dần sau"
- [ ] Đã kiểm tra phạm vi quyền (scope) cấp cho MCP server là tối thiểu cần thiết, không cấp full-access nếu chỉ cần đọc
- [ ] Đã test trên 1 kênh/1 workspace phụ trước khi áp dụng lên kênh/dữ liệu chính
- [ ] Biết rõ cách thu hồi quyền truy cập nếu cần dừng tích hợp
- [ ] Đã ghi lại cấu hình MCP server đã dùng vào tài liệu cá nhân để nhớ lại sau vài tháng

## Expected Output
1 MCP server hoặc tích hợp API hoạt động đúng use case đã định nghĩa từ đầu, có thể bật/tắt độc lập mà không ảnh hưởng tới các workflow Claude Code khác. Đi kèm 1 ghi chú ngắn về phạm vi quyền đã cấp và cách thu hồi nếu cần.

## Common mistakes
- Cấp quyền OAuth quá rộng (full read-write toàn bộ workspace) trong khi use case chỉ cần đọc 1 channel — tạo rủi ro bảo mật không cần thiết
- Setup xong tích hợp rồi để Claude tự hành động ngay trên kênh thật mà chưa test kỹ — gửi nhầm message, sửa nhầm page Notion không thể hoàn tác dễ dàng
- Không tách biệt môi trường test và production (dùng luôn channel/workspace chính để thử nghiệm), dẫn tới lỗi ảnh hưởng dữ liệu thật
- Quên rằng MCP server cần được duy trì và có thể cần cập nhật — không phải "cài 1 lần là chạy mãi mãi không cần để ý"
- Để Claude tự động hoàn toàn với các hành động không thể hoàn tác (gửi email, đăng tin nhắn) mà không có bước con người xác nhận trước khi gửi

## Phiên bản Claude Code
Đây là trọng tâm hoàn toàn của Claude Code + MCP, không có phiên bản Claude Chat tương đương vì bản chất là kết nối công cụ ngoài vào CLI. Cấu hình qua `claude mcp add` hoặc khai báo trực tiếp trong `.claude/settings.json`. Cấu trúc gợi ý:
```
project/
  .claude/
    settings.json      # khai báo MCP servers, phạm vi quyền
  CLAUDE.md             # mô tả use case, quy tắc khi nào Claude được tự hành động
```
Dùng `claude mcp list` để kiểm tra các server đã đăng ký, gõ `/mcp` trong session để xem trạng thái kết nối/auth của từng server. Với mọi hành động có tác động thật ra bên ngoài (gửi Slack message, tạo page Notion, gửi email), giữ nguyên tắc trong CLAUDE.md của project: Claude chuẩn bị nội dung, bạn xác nhận trước khi gửi — không để tự động hoàn toàn cho các hành động không thể hoàn tác.

## Khi nào nên dùng Deep Research
Hầu như không cần — đây là việc kỹ thuật cấu hình dựa trên tài liệu chính thức của MCP và API từng công cụ, thường có sẵn hướng dẫn rõ ràng. Ngoại lệ: nếu công cụ đích ít phổ biến hoặc tài liệu MCP/API của nó thay đổi thường xuyên (breaking changes giữa các phiên bản), dùng 1 lượt research nhanh để xác nhận cú pháp/phiên bản API mới nhất trước khi setup — không nhất thiết cần quy trình Deep Research đầy đủ.

# Deploy và kiểm tra ứng dụng sau khi build

## Mục tiêu
Deploy 1 thay đổi lên production (hoặc staging) và xác nhận nó hoạt động đúng — không chỉ "build thành công" mà là "chạy đúng như kỳ vọng" — trong vòng 15-30 phút kể cả bước kiểm tra sau deploy.

## Khi nào dùng
- Chuẩn bị deploy 1 tính năng/fix đã test xong lên môi trường thật (staging hoặc production).
- Sau khi deploy xong, cần 1 quy trình kiểm tra chuẩn thay vì "thấy site load được là yên tâm".
- Không dùng workflow này để thay thế CI/CD tự động đã thiết lập — đây là quy trình cho người tự deploy tay hoặc cần kiểm tra kỹ hơn pipeline mặc định, tham khảo thêm workflow 13.01 nếu muốn tự động hoá toàn bộ.

## Input
- Môi trường deploy (staging/production), platform (Vercel, Railway, VPS, Docker...).
- Thay đổi đang deploy là gì (tính năng mới, fix, migration database có không).
- Có rollback plan sẵn không (bản build trước đó, cách revert nhanh).
- (Tuỳ chọn) Danh sách endpoint/luồng quan trọng cần kiểm tra sau deploy (checkout, login, API chính).

## Prompt Template
```
Tôi chuẩn bị deploy thay đổi sau lên {{staging/production}}, dùng {{platform: Vercel/Railway/Docker/VPS...}}.

Thay đổi đang deploy: {{mô tả ngắn tính năng/fix}}
Có migration database không: {{có/không, chi tiết nếu có}}
Rollback plan: {{cách quay lại bản trước nếu có sự cố}}

Yêu cầu:
1. Trước khi deploy: kiểm tra checklist pre-deploy (build local pass, test pass, env vars đã set đúng ở môi trường đích, migration đã review).
2. Chạy lệnh deploy (hoặc hướng dẫn từng bước nếu cần tôi tự làm phần không thể tự động).
3. Sau khi deploy: kiểm tra health check / endpoint chính còn phản hồi đúng không.
4. Kiểm tra log ngay sau deploy trong 5-10 phút đầu — có lỗi mới xuất hiện không so với trước deploy.
5. Nếu phát hiện vấn đề, đề xuất rollback ngay, không cố sửa nóng trên production.

Danh sách luồng quan trọng cần verify tay sau deploy: {{liệt kê endpoint/tính năng chính}}
```

## Checklist
- [ ] Build local pass và test suite pass trước khi deploy — không deploy code chưa test qua.
- [ ] Biến môi trường ở môi trường đích đã đúng, đặc biệt secrets/API keys mới nếu tính năng cần.
- [ ] Nếu có migration database, đã review kỹ (đặc biệt migration không thể rollback dễ dàng).
- [ ] Sau deploy, tự tay kiểm tra ít nhất 1 luồng chính (không chỉ tin "deploy thành công" từ log build).
- [ ] Theo dõi log/error tracking trong ít nhất 10-15 phút đầu sau deploy.
- [ ] Xác nhận rollback plan sẵn sàng và biết chính xác lệnh/thao tác để revert nếu cần.

## Expected Output
Xác nhận rõ ràng: deploy thành công + đã verify tay ít nhất 1 luồng chính hoạt động đúng + không có lỗi mới trong log 10-15 phút đầu. Nếu có vấn đề, có quyết định rõ ràng (rollback ngay hay theo dõi thêm) thay vì để mơ hồ "chắc không sao đâu". Không chấp nhận "deploy xong" chỉ dựa trên thông báo build/CI xanh mà chưa verify hành vi thật.

## Common mistakes
- Coi "build thành công" đồng nghĩa "deploy đúng" — build pass chỉ nghĩa là code compile được, không đảm bảo logic đúng hay env vars đúng ở môi trường thật.
- Deploy migration database không có kế hoạch rollback — một số migration (xoá cột, đổi kiểu dữ liệu) không thể revert dễ dàng, cần tách riêng và cẩn trọng hơn deploy code thường.
- Không kiểm tra log ngay sau deploy, chỉ quay lại xem sau vài giờ — lỗi mới thường lộ ra ngay phút đầu, phát hiện sớm giúp rollback nhanh trước khi ảnh hưởng nhiều người dùng.
- Deploy trực tiếp lên production mà bỏ qua staging khi có staging sẵn — tiết kiệm 5 phút nhưng rủi ro cao hơn nhiều nếu có sự cố.
- Cố sửa nóng (hotfix) ngay trên production khi phát hiện lỗi thay vì rollback trước — rollback luôn an toàn hơn, sửa nóng dễ tạo thêm lỗi mới trong lúc đang hoảng.

## Phiên bản Claude Code
Đây là workflow Claude Code thuần, tận dụng khả năng chạy lệnh CLI và đọc log trực tiếp.

Quy trình cụ thể:
1. Trong thư mục project, chạy `claude`, yêu cầu chạy checklist pre-deploy trước: build local, chạy test suite qua Bash, kiểm tra file `.env.example` khớp với biến môi trường cần thiết.
2. Nếu dùng skill sẵn có (vd `engineering:deploy-checklist`), gọi trước để có checklist chuẩn thay vì tự nhớ từng bước.
3. Lệnh mẫu: `claude "Chạy npm run build và npm test, nếu pass thì deploy lên Vercel bằng vercel --prod, sau đó curl endpoint /api/health và báo kết quả."`
4. Với platform có CLI (Vercel, Railway, flyctl, Docker), để Claude Code tự chạy lệnh deploy qua Bash thay vì bạn chuyển sang terminal riêng — giữ toàn bộ quy trình (build → test → deploy → verify) trong 1 phiên có log liền mạch.
5. Sau deploy, yêu cầu Claude Code tự kiểm tra: gọi thử endpoint chính bằng `curl`, đọc log qua CLI của platform (`vercel logs`, `railway logs`, `docker logs`) trong vài phút đầu, báo cáo có lỗi mới không so với trước deploy.
6. Nếu phát hiện lỗi, để Claude Code chuẩn bị sẵn lệnh rollback (`vercel rollback`, `git revert` + redeploy) và hỏi xác nhận trước khi chạy — rollback là hành động ảnh hưởng production, nên xác nhận tay trước khi thực thi.
7. Dùng TodoWrite để theo dõi từng bước (pre-check → deploy → verify → monitor) khi deploy có nhiều bước thủ công xen kẽ tự động.

## Khi nào nên dùng Deep Research
Hiếm khi cần cho deploy thông thường. Ngoại lệ: khi chuyển sang 1 platform/công cụ deploy mới lần đầu dùng (vd lần đầu deploy Docker lên 1 VPS cụ thể, hoặc dùng 1 CI/CD service mới), nên tra cứu tài liệu chính thức của platform đó trước để nắm đúng quy trình và các lỗi thường gặp, tránh làm theo trí nhớ chung chung có thể đã lỗi thời so với phiên bản hiện tại của platform.

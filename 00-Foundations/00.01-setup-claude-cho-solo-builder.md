# Thiết lập Claude cho Solo Builder (Setup Chat + Code + Projects)

## Mục tiêu
Dựng xong bộ khung làm việc với Claude trong một buổi (60-90 phút): tài khoản + Projects trên Claude Chat được tổ chức theo lĩnh vực công việc thật, Claude Code cài đặt và chạy được trên máy, và một CLAUDE.md gốc phản ánh đúng cách bạn làm việc — để từ hôm sau không phải setup lại từ đầu mỗi lần mở chat mới.

## Khi nào dùng
- Lần đầu dùng Claude nghiêm túc cho công việc (không phải thử chơi)
- Mới đổi máy, cài lại môi trường, hoặc bắt đầu một mảng công việc mới (vd: từ freelance content sang build sản phẩm)
- Cảm thấy đang dùng Claude Chat "chay" — mỗi lần chat đều phải giải thích lại bối cảnh từ đầu
- KHÔNG cần làm lại workflow này nếu bạn chỉ thêm 1 project mới vào hệ thống đã có — lúc đó chỉ cần lặp lại bước tạo Project, không cần setup toàn bộ

## Input
- Danh sách các mảng công việc chính của bạn (vd: 3-5 mảng: sản phẩm A, content, vận hành, tài chính cá nhân...)
- Đã cài Node.js (để cài Claude Code qua npm) hoặc biết cách cài qua trình cài đặt riêng
- Biết mình sẽ dùng Claude cho việc gì nhiều nhất trong 30 ngày tới (research, code, viết lách, ra quyết định...) — để ưu tiên setup đúng chỗ trước

## Prompt Template
```
Bạn là một trợ lý setup workspace cho tôi — một solo builder (tự làm mọi việc: sản phẩm, content, vận hành, không có team). Tôi vừa cài Claude Chat và Claude Code, muốn dựng bộ khung làm việc gọn, không lan man.

Bối cảnh về tôi:
- Các mảng công việc chính: {{liệt kê 3-5 mảng, vd: sản phẩm SaaS X, viết newsletter, tư vấn freelance}}
- Công cụ tôi đang dùng song song: {{vd: Notion, Google Drive, GitHub, Excel}}
- Việc tôi sẽ dùng Claude nhiều nhất: {{vd: viết code, research thị trường, viết content, ra quyết định kinh doanh}}
- Tần suất làm việc: {{vd: làm một mình, 6-8 tiếng/ngày, chuyển qua lại nhiều task nhỏ}}

Yêu cầu:
1. Đề xuất cấu trúc Projects trên Claude Chat: bao nhiêu project, tên gì, project nào chứa custom instructions gì (dựa trên các mảng công việc tôi liệt kê).
2. Với mỗi Project, gợi ý 3-5 tài liệu nền tảng tôi nên upload vào Project knowledge (vd: mô tả sản phẩm, tone giọng văn, quy trình chuẩn).
3. Đề xuất nội dung khung cho custom instructions cấp Project (không phải cấp tài khoản) — ngắn gọn, phản ánh đúng vai trò tôi muốn Claude đóng trong project đó.
4. Liệt kê các quyết định tôi cần chốt trước khi bắt đầu dùng (vd: có dùng Claude Code song song không, có kết nối Google Drive/GitHub không).

Định dạng output: bảng cho cấu trúc Projects, danh sách gạch đầu dòng cho phần còn lại. Ngắn gọn, hành động được ngay, không lý thuyết dài dòng.
```

## Checklist
- [ ] Đã tạo ít nhất 1 Project cho mỗi mảng công việc chính, tên rõ ràng (không đặt tên chung chung "Project 1")
- [ ] Đã upload tối thiểu 2-3 tài liệu nền tảng vào mỗi Project (không để Project knowledge trống)
- [ ] Đã cài Claude Code, chạy thử `claude` trong một thư mục test và xác nhận nó đọc/ghi file được
- [ ] Đã viết CLAUDE.md gốc (xem workflow 00.03) và đặt đúng vị trí (`~/.claude/CLAUDE.md` cho global, hoặc trong từng project code)
- [ ] Đã thử một task thật (không phải task demo) trên cả Claude Chat và Claude Code để cảm nhận khác biệt
- [ ] Đã xoá/gộp các Project trùng lặp hoặc không còn dùng từ trước

## Expected Output
Một hệ thống Projects trên Claude Chat (thường 3-6 project, mỗi cái có custom instructions + knowledge riêng), Claude Code chạy được trên máy với ít nhất 1 lần test thành công, và 1 file CLAUDE.md gốc. Không cần hoàn hảo ngay — mục tiêu là có khung để dùng thật, rồi tinh chỉnh dần sau mỗi tuần.

## Common mistakes
- Tạo quá nhiều Project nhỏ lẻ (10+) ngay từ đầu — dẫn đến phân mảnh, quên project nào chứa gì. Nên bắt đầu ít (3-5), gộp theo mảng lớn, tách nhỏ dần khi thật sự cần.
- Upload tài liệu vào Project knowledge nhưng không cập nhật khi tài liệu gốc thay đổi — Claude vẫn trả lời theo bản cũ mà người dùng không biết.
- Viết custom instructions quá dài, nhồi hết mọi quy tắc — Claude Chat có xu hướng "quên" ưu tiên khi instruction quá dài, nên phần quan trọng nhất bị lu mờ.
- Cài Claude Code nhưng không hiểu working directory là gì — chạy lệnh ở sai thư mục rồi ngạc nhiên vì Claude không thấy file cần thiết.
- Setup xong rồi không dùng thật ngay — để 2 tuần sau quay lại thì quên hết cấu trúc đã dựng, phải làm lại.

## Phiên bản Claude Code
Đây là phần bắt buộc phải có Claude Code, không thể thay thế hoàn toàn bằng Claude Chat vì liên quan trực tiếp đến việc cài đặt CLI:
1. Cài đặt: `npm install -g @anthropic-ai/claude-code` (hoặc trình cài native theo hệ điều hành).
2. Xác thực: chạy `claude` lần đầu, đăng nhập bằng tài khoản Claude (Pro/Max hoặc API key).
3. Test nhanh: vào một thư mục project thật, chạy `claude`, hỏi nó liệt kê cấu trúc thư mục — xác nhận nó đọc đúng file thật, không phải trả lời chung chung.
4. Tạo `CLAUDE.md` ở thư mục gốc của từng project code quan trọng (khác với CLAUDE.md global ở `~/.claude/`) — đây là nơi ghi quy ước riêng của project đó (ngôn ngữ, framework, style code).
5. Nếu dùng nhiều project code, cân nhắc thêm alias hoặc script khởi động nhanh (vd: mở terminal đúng thư mục rồi tự chạy `claude`).

## Khi nào nên dùng Deep Research
Workflow này gần như không cần Deep Research — đây là việc setup cá nhân dựa trên thông tin bạn đã biết về chính mình (mảng công việc, công cụ đang dùng), không phải câu hỏi cần tổng hợp nhiều nguồn bên ngoài. Ngoại lệ đáng cân nhắc: nếu bạn đang phân vân giữa nhiều cách tổ chức Projects/workspace (vd: so sánh cách nhiều solo builder khác cấu trúc Claude Projects của họ) và muốn khảo sát 5-10 bài viết/thảo luận thực tế trước khi quyết định cấu trúc dài hạn, lúc đó Deep Research giúp tiết kiệm thời gian tự tìm đọc từng nguồn.

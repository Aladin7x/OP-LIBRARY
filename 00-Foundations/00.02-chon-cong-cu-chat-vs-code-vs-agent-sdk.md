# Chọn đúng công cụ: Claude Chat vs Claude Code vs Agent SDK

## Mục tiêu
Trong dưới 2 phút, chọn đúng công cụ (Claude Chat / Claude Code / Agent SDK) cho một task cụ thể, tránh tình trạng dùng sai công cụ khiến task mất gấp 2-3 lần thời gian cần thiết (vd: copy-paste code qua lại Chat thay vì để Claude Code sửa file trực tiếp, hoặc dựng Agent SDK cho việc chỉ cần hỏi một lần).

## Khi nào dùng
- Trước khi bắt đầu bất kỳ task nào có liên quan đến file, code, hoặc quy trình lặp lại — dừng 30 giây để chọn đúng công cụ trước khi lao vào làm
- Khi thấy mình đang "vật lộn" với một công cụ (vd: copy-paste code từ Claude Chat vào editor liên tục) — dấu hiệu chọn sai công cụ
- Khi cân nhắc có nên tự động hoá một quy trình đang làm thủ công lặp đi lặp lại (ứng viên cho Agent SDK)
- KHÔNG cần dùng workflow này cho các câu hỏi một lần, không liên quan file/hệ thống — cứ mở Claude Chat mà hỏi

## Input
- Mô tả ngắn về task: đầu vào là gì, đầu ra cần là gì
- Task có động vào file/thư mục thật trên máy không, hay chỉ cần văn bản/ý tưởng
- Task có lặp lại định kỳ không (hàng ngày/tuần) hay chỉ làm một lần
- Task có cần chạy tự động, không cần bạn ngồi tương tác từng bước không

## Prompt Template
```
Tôi cần chọn công cụ Claude phù hợp cho task sau. Hãy phân tích và khuyến nghị.

Mô tả task: {{mô tả task cụ thể}}
Đầu vào: {{loại dữ liệu đầu vào — văn bản, file code, file Excel, ảnh...}}
Đầu ra mong muốn: {{kết quả cụ thể cần có}}
Task này có động vào file/thư mục thật trên máy tôi không: {{có/không, nếu có thì loại file gì}}
Tần suất: {{làm một lần / lặp lại định kỳ / chạy tự động không cần tôi can thiệp}}
Mức độ tôi muốn kiểm soát từng bước: {{muốn xem và duyệt từng bước / chỉ cần kết quả cuối}}

Yêu cầu: Khuyến nghị 1 trong 3 công cụ (Claude Chat / Claude Code / Agent SDK), giải thích lý do trong 2-3 câu, và nếu có phương án kết hợp (vd: research trên Chat rồi thực thi bằng Code) thì nêu rõ trình tự.
```

## Checklist
- [ ] Đã xác định task có động vào file thật hay không — nếu có, ưu tiên Claude Code thay vì copy-paste qua Chat
- [ ] Đã xác định task có lặp lại định kỳ không — nếu có và ổn định, cân nhắc Agent SDK hoặc script hoá
- [ ] Đã thử tưởng tượng luồng thao tác thực tế (bao nhiêu lần copy-paste, bao nhiêu lần chuyển cửa sổ) trước khi chốt công cụ
- [ ] Nếu chọn Agent SDK, đã xác nhận task đủ ổn định và lặp lại đủ nhiều để bõ công dựng (thường >10 lần/tháng)
- [ ] Không chọn công cụ phức tạp hơn mức cần thiết chỉ vì nó "nghe chuyên nghiệp hơn"

## Expected Output
Một quyết định rõ ràng: dùng công cụ nào, vì sao, và nếu cần phối hợp nhiều công cụ thì theo trình tự nào. Ví dụ: "Task viết báo cáo phân tích thị trường → Claude Chat + Projects (không động file, không lặp lại đều đặn). Task refactor 20 file code theo pattern mới → Claude Code (động file thật, cần xem diff từng bước). Task tự động tổng hợp tin tức ngành mỗi sáng gửi qua email → Agent SDK (lặp lại hàng ngày, không cần người ngồi tương tác)."

## Common mistakes
- Dùng Claude Chat cho việc sửa code nhiều file — dẫn đến copy-paste thủ công, dễ sai sót, mất context giữa các lần paste. Nguyên nhân: quen thuộc với giao diện chat hơn, ngại chuyển sang terminal.
- Dựng Agent SDK cho một việc chỉ làm 1-2 lần — tốn thời gian setup hơn nhiều lần so với việc tự làm thủ công hoặc hỏi Claude Chat trực tiếp.
- Dùng Claude Code cho các câu hỏi tư duy/chiến lược không liên quan file — Claude Code tối ưu cho thao tác trên codebase, không phải nơi lý tưởng để brainstorm ý tưởng kinh doanh.
- Không tách biệt "task cần kiểm soát từng bước" và "task chỉ cần kết quả cuối" — dẫn đến dùng Claude Code (vốn cho phép xem diff, duyệt từng thay đổi) một cách hời hợt, hoặc ngược lại review thủ công kết quả Chat trả về vốn nên tự động hoá.
- Đánh giá sai tần suất lặp lại — nghĩ task "sẽ làm thường xuyên" nhưng thực tế chỉ làm 1 lần, gây lãng phí công sức tự động hoá.

## Phiên bản Claude Code
Đây chính là công cụ trung tâm của workflow này khi task liên quan file/code. Quy tắc thực dụng: nếu task cần đọc/sửa/tạo từ 1 file trở lên trên máy, hoặc cần chạy lệnh (test, build, git), luôn ưu tiên Claude Code trong thư mục dự án — mở terminal, `cd` vào đúng project, chạy `claude`, mô tả task bằng ngôn ngữ tự nhiên. Với Agent SDK: chỉ cân nhắc khi đã xác nhận quy trình ổn định qua ít nhất vài lần làm thủ công bằng Claude Code trước, sau đó mới đóng gói thành script/agent tự động chạy định kỳ (vd: cron job gọi Agent SDK).

## Khi nào nên dùng Deep Research
Hầu như không cần cho chính việc "chọn công cụ" — đây là quyết định dựa trên đặc điểm task của bạn, tự bạn biết rõ nhất, không cần tổng hợp nguồn ngoài. Ngoại lệ: nếu bạn đang cân nhắc dựng một hệ thống Agent SDK phức tạp (nhiều agent phối hợp, tích hợp nhiều API) và muốn khảo sát các pattern kiến trúc đã được người khác thử nghiệm trước khi tự thiết kế, lúc đó Deep Research trên 5-10 nguồn (docs, case study, bài kỹ thuật) sẽ tiết kiệm thời gian dò dẫm thử sai.

# Phân tích dữ liệu kinh doanh từ file CSV/Excel

## Mục tiêu
Có được báo cáo phân tích dữ liệu kinh doanh (doanh thu, chi phí, khách hàng, đơn hàng...) đủ sâu để ra quyết định trong vòng 15-20 phút, thay vì mất nửa ngày tự lọc pivot table trên Excel.

## Khi nào dùng
- Bạn có 1 file CSV/Excel dữ liệu (đơn hàng, giao dịch, khách hàng...) và cần tìm insight cụ thể (xu hướng, bất thường, top/bottom performer) chứ không chỉ xem số liệu thô.
- File đủ lớn để tự lọc/pivot tay mất thời gian, nhưng chưa đến mức cần hệ thống BI riêng.
- Cần trả lời nhanh 1 câu hỏi kinh doanh cụ thể ("tháng nào doanh thu giảm mạnh nhất và vì sao") mà không muốn tự viết công thức Excel phức tạp.
- KHÔNG dùng nếu chỉ cần xem 1 con số đơn giản (tổng/trung bình) — mở Excel tính tay nhanh hơn.

## Input
- File CSV/Excel gốc (đường dẫn hoặc dán trực tiếp vài dòng đầu để Claude hiểu cấu trúc cột).
- Câu hỏi kinh doanh cụ thể cần trả lời (không phải "phân tích giúp tôi" chung chung).
- Ngữ cảnh cần biết: đơn vị tiền tệ, khung thời gian dữ liệu, có giá trị nào cần loại trừ (test data, đơn huỷ...) không.
- (Tuỳ chọn) Kỳ vọng định dạng output: bảng, biểu đồ mô tả bằng lời, hay danh sách insight.

## Prompt Template
```
Bạn là chuyên gia phân tích dữ liệu kinh doanh. Tôi có file dữ liệu sau, giúp tôi trả lời câu hỏi cụ thể.

Mô tả file: {{tên file, số dòng ước tính, các cột chính}}
Vài dòng dữ liệu mẫu (hoặc toàn bộ nếu file nhỏ):
{{dán dữ liệu dạng CSV/bảng}}

Ngữ cảnh cần biết:
- Đơn vị: {{VND/USD, đơn vị số lượng...}}
- Khung thời gian: {{từ ngày...đến ngày...}}
- Loại trừ: {{giá trị/dòng cần bỏ qua nếu có, vd đơn test, đơn huỷ}}

Câu hỏi cần trả lời: {{câu hỏi kinh doanh cụ thể, vd "tháng nào doanh thu giảm mạnh nhất so với tháng trước, và nhóm sản phẩm nào đóng góp nhiều nhất vào mức giảm đó"}}

Yêu cầu:
1. Trả lời trực tiếp câu hỏi bằng số liệu cụ thể tính từ dữ liệu trên.
2. Chỉ ra 2-3 insight phụ đáng chú ý nếu có (bất thường, xu hướng) — không suy diễn ngoài dữ liệu.
3. Nếu dữ liệu không đủ để trả lời chắc chắn, nói rõ thiếu gì.

Định dạng output: câu trả lời chính + bảng số liệu hỗ trợ + insight phụ (nếu có).
```

## Checklist
- [ ] Đã kiểm tra dữ liệu đầu vào sạch (không lẫn dòng header lặp, không có giá trị null/lỗi định dạng phá vỡ tính toán)
- [ ] Câu hỏi đủ cụ thể, có thể trả lời bằng số liệu, không mơ hồ kiểu "phân tích tổng quan"
- [ ] Đã nêu rõ đơn vị và khung thời gian để tránh Claude hiểu nhầm hoặc tự giả định sai
- [ ] Đã đối chiếu nhanh 1-2 con số Claude đưa ra với dữ liệu gốc (tính tay hoặc filter nhanh) để xác nhận không tính sai
- [ ] Output có insight phụ thực sự dựa trên dữ liệu, không phải nhận xét chung chung không kiểm chứng được

## Expected Output
Câu trả lời trực tiếp cho câu hỏi đặt ra, kèm số liệu cụ thể và 1 bảng hỗ trợ (top N, breakdown theo nhóm...). Nếu có insight phụ, phải trích được ra từ dữ liệu cụ thể (vd "nhóm sản phẩm X giảm 30% trong khi các nhóm khác ổn định"), không phải suy đoán.

## Common mistakes
- Dán dữ liệu không đầy đủ (chỉ vài dòng mẫu) nhưng hỏi câu hỏi cần tính trên toàn bộ tập dữ liệu (vd "tổng doanh thu") — Claude Chat chỉ tính được trên phần dữ liệu thực sự có trong context, không tự suy ra phần thiếu.
- Không loại trừ dữ liệu rác (đơn test, dòng trùng, giá trị âm bất thường) trước khi phân tích — kết quả bị lệch mà không nhận ra.
- Đặt câu hỏi quá rộng ("phân tích giúp tôi") khiến Claude tự chọn góc nhìn, có thể không phải góc bạn cần — luôn hỏi câu hỏi kinh doanh cụ thể.
- Không kiểm tra lại ít nhất 1 con số quan trọng — với dữ liệu lớn dán qua Claude Chat (không phải code thực thi), luôn có rủi ro tính sai cần đối chiếu.
- Nhầm cột do tên cột không rõ ràng (vd 2 cột đều tên "amount" nhưng 1 cột là giá gốc, 1 cột là giá sau giảm) — không giải thích rõ ý nghĩa từng cột khiến Claude hiểu sai.

## Phiên bản Claude Code
Với file nhỏ-vừa (vài nghìn dòng, cần 1 câu trả lời nhanh), Claude Chat với Analysis tool (chạy Python trong chat) đã đủ và nhanh hơn setup project. Chuyển sang Claude Code khi: file lớn (hàng chục nghìn dòng+), cần phân tích lặp lại định kỳ, hoặc cần kết hợp nhiều file.

Cấu trúc project gợi ý:
```
data-analysis/
  data/
    raw/                      # file gốc, không sửa trực tiếp
    processed/                 # sau khi làm sạch
  scripts/
    clean.py                   # xử lý null, loại trừ dòng rác
    analyze.py                 # tính toán, trả lời câu hỏi cụ thể
  reports/
    2026-08-05-doanh-thu.md
```

- Dùng `pandas` để đọc và xử lý file lớn chính xác hơn dán tay vào chat: `df = pd.read_csv("data/raw/orders.csv")`, kiểm tra `df.info()`, `df.isnull().sum()` trước khi phân tích.
- Yêu cầu Claude Code viết script `analyze.py` trả lời đúng câu hỏi, in ra kết quả kèm code đã dùng để tính — bạn xem được logic tính toán, không phải "hộp đen".
- Với phân tích lặp lại hàng tuần/tháng (vd báo cáo doanh thu định kỳ), lưu script lại và chỉ đổi file input — chạy `python scripts/analyze.py data/raw/thang-8.csv` mỗi lần thay vì viết lại prompt từ đầu.
- Nếu dữ liệu nằm trong database thay vì file, xem thêm 08.02 để viết SQL truy vấn trực tiếp thay vì export CSV thủ công.

## Khi nào nên dùng Deep Research
Hầu như không cần cho việc phân tích dữ liệu nội bộ của chính bạn — đây là việc tính toán trên dữ liệu có sẵn, không phải tổng hợp thông tin bên ngoài. Chỉ cân nhắc Deep Research khi:
- Cần đối chiếu số liệu nội bộ với benchmark ngành/thị trường bên ngoài (vd "doanh thu tăng trưởng của tôi so với trung bình ngành thế nào") — lúc này cần tổng hợp nguồn dữ liệu công khai bên ngoài dữ liệu nội bộ.
- Cần chọn phương pháp thống kê/mô hình phân tích phù hợp mà bạn chưa quen (vd nên dùng phương pháp nào để phát hiện seasonality) và muốn tham khảo cách tiếp cận chuẩn trước khi tự áp dụng.

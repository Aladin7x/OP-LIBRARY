# Thiết kế Agent đơn giản cho tác vụ lặp lại

## Mục tiêu
Thiết kế xong một agent single-purpose (1 vòng lặp, 1 bộ tool cố định) trong vòng 30-60 phút, chạy được task lặp lại (vd. đọc email → phân loại → trả lời mẫu; đọc file → validate → xuất báo cáo) mà không cần bạn ngồi canh từng bước.

## Khi nào dùng
- Task bạn đang làm tay lặp đi lặp lại ≥ 3 lần/tuần, có quy trình rõ ràng (input → xử lý → output cố định).
- Task cần Claude tự quyết định gọi tool nào (đọc file, gọi API, chạy script) thay vì bạn copy-paste qua lại nhiều lần.
- KHÔNG dùng khi: task chỉ chạy 1 lần duy nhất (viết prompt thường nhanh hơn), hoặc task cần phán đoán sáng tạo không có tiêu chí rõ (agent sẽ tự chế bừa).

## Input
- Mô tả quy trình hiện tại bạn đang làm tay, từng bước một (càng chi tiết càng tốt).
- Danh sách tool/dữ liệu agent cần truy cập (file, API, database, terminal).
- Tiêu chí "xong việc" — khi nào agent biết dừng, khi nào biết là đã làm đúng.
- (Tuỳ chọn) Ví dụ input/output mẫu 2-3 case thực tế để agent bắt chước.

## Prompt Template
```
Bạn là {{vai trò agent, vd "trợ lý phân loại và trả lời email hỗ trợ khách hàng"}}.

Nhiệm vụ lặp lại cần tự động hoá:
{{mô tả quy trình hiện tại đang làm tay, từng bước}}

Input agent sẽ nhận:
{{định dạng input, vd "1 email dạng text, gồm subject + body"}}

Tool agent được phép dùng:
{{liệt kê tool, vd "đọc file CSV danh sách khách hàng, gọi search nội bộ, không được gửi email trực tiếp"}}

Quy tắc ra quyết định:
1. {{quy tắc 1, vd "nếu email hỏi về giá → dùng template A"}}
2. {{quy tắc 2, vd "nếu không chắc chắn → gắn nhãn 'cần người duyệt', không tự trả lời"}}

Điều kiện dừng / báo lỗi:
{{khi nào agent nên dừng lại và hỏi bạn thay vì tự quyết}}

Output mong muốn: {{định dạng, vd "1 bảng: email_id | phân loại | draft trả lời | mức độ tự tin"}}

Ví dụ input/output mẫu:
{{2-3 ví dụ thực tế}}
```

## Checklist
- [ ] Quy trình đã được viết thành các bước rời rạc, không mơ hồ (không có bước "dùng phán đoán tốt")
- [ ] Đã xác định rõ agent được phép tự quyết cái gì, cái gì bắt buộc phải hỏi lại bạn
- [ ] Đã test với ít nhất 3 input thực tế khác nhau (bao gồm 1 input "khó" hoặc bất thường)
- [ ] Đã có điều kiện dừng rõ ràng (tránh agent tự lặp vô hạn)
- [ ] Đã kiểm tra output có đúng định dạng để bạn dùng ngay, không cần chỉnh tay

## Expected Output
Một bản mô tả agent hoàn chỉnh (system prompt + quy tắc + tool list) mà bạn có thể dán thẳng vào Claude Chat (Project instructions) hoặc dùng làm system prompt cho Claude Code/Agent SDK. Chạy thử với 3 input mẫu phải ra kết quả đúng ≥ 2/3 lần không cần sửa tay.

## Common mistakes
- Giao quy trình mơ hồ ("xử lý email cho hợp lý") — agent sẽ tự chế quy tắc riêng, không đoán trước được hành vi.
- Không giới hạn tool — cho agent quyền truy cập quá rộng (vd toàn bộ filesystem) trong khi chỉ cần đọc 1 file, dẫn đến rủi ro và hành vi khó kiểm soát.
- Quên định nghĩa "khi nào dừng" — agent cứ lặp tool call vì nghĩ chưa xong việc.
- Test chỉ với 1 input "đẹp" duy nhất rồi coi là xong — không phát hiện được case biên (input thiếu field, input rỗng, input sai định dạng).
- Không log lại quyết định của agent — khi nó trả lời sai, không biết agent đã "nghĩ" gì để sửa.

## Phiên bản Claude Code
Đây là workflow phù hợp Claude Code hơn nếu agent cần chạy lặp lại tự động (không phải 1 lần dùng thử trong chat).

Cấu trúc project gợi ý:
```
my-agent/
  .claude/
    agents/
      email-classifier.md      # subagent definition, frontmatter: name, description, tools
  scripts/
    run.py                     # entrypoint gọi agent qua Agent SDK hoặc CLI
  data/
    input/
    output/
```

- Định nghĩa agent như một **subagent** trong `.claude/agents/<ten>.md` với frontmatter khai báo `tools` cụ thể (vd chỉ `Read, Bash` — không cho `Write` nếu agent chỉ cần đọc và phân loại).
- Chạy thử nhanh bằng lệnh: `claude "Chạy subagent email-classifier trên file data/input/today.csv"` hoặc gọi trực tiếp qua Claude Agent SDK trong `scripts/run.py` nếu cần chạy theo lịch (cron).
- Nếu cần lặp định kỳ, kết hợp với Windows Task Scheduler hoặc `mcp__scheduled-tasks__create_scheduled_task` để agent tự chạy hàng ngày/hàng giờ mà không cần bạn gõ lệnh.
- Giữ agent "đơn nhiệm" — 1 subagent làm 1 việc; nếu quy trình có nhiều bước khác biệt (phân loại → soạn thư → gửi duyệt), tách thành nhiều subagent nhỏ thay vì nhồi hết vào 1 prompt dài (xem thêm 06.02).

## Khi nào nên dùng Deep Research
Hiếm khi cần cho workflow này — thiết kế agent đơn giản chủ yếu là vấn đề mô tả quy trình rõ ràng, không phải research. Chỉ cân nhắc Deep Research khi:
- Bạn chưa biết agent framework/pattern nào phù hợp (vd nên dùng single-prompt hay ReAct loop) và cần so sánh nhiều nguồn tài liệu kỹ thuật mới nhất.
- Task liên quan đến một API/tool bên thứ ba bạn chưa quen, cần tổng hợp docs + rate limit + auth flow trước khi thiết kế tool call.

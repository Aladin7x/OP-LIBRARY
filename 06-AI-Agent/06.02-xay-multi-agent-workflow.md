# Xây dựng multi-agent workflow (orchestrator + subagent)

## Mục tiêu
Tách một task phức tạp (nhiều bước, nhiều loại chuyên môn) thành 1 orchestrator + 2-4 subagent chuyên biệt, chạy được end-to-end trong 1 lệnh mà kết quả mỗi bước kiểm chứng được riêng lẻ — thay vì 1 prompt khổng lồ dễ lạc hướng giữa chừng.

## Khi nào dùng
- Task có nhiều giai đoạn khác biệt về "loại tư duy" (vd: research → viết code → review → test) — mỗi giai đoạn nên có context riêng, không lẫn lộn.
- Task đủ dài để 1 agent chạy 1 mình dễ mất context hoặc lạc hướng (context window bị pha loãng bởi quá nhiều bước không liên quan).
- Cần chạy song song nhiều nhánh độc lập (vd: research 3 chủ đề khác nhau) để tiết kiệm thời gian.
- KHÔNG dùng khi: task đơn giản, tuyến tính, 1 agent làm gọn trong vài bước — multi-agent sẽ chỉ thêm overhead điều phối không cần thiết (dùng 06.01 thay thế).

## Input
- Sơ đồ quy trình: các giai đoạn chính và thứ tự phụ thuộc (bước nào phải xong trước bước nào, bước nào chạy song song được).
- Với mỗi giai đoạn: input cần, output kỳ vọng, tool cần dùng.
- Tiêu chí orchestrator dùng để quyết định "subagent này xong chưa, có cần chạy lại không".
- (Tuỳ chọn) Ràng buộc chi phí/thời gian — vd giới hạn số vòng lặp tối đa mỗi subagent.

## Prompt Template
```
Bạn là Orchestrator cho quy trình: {{tên quy trình, vd "nghiên cứu + viết báo cáo phân tích đối thủ"}}.

Các giai đoạn (subagent) cần điều phối, theo thứ tự:
1. {{tên subagent 1}} — nhiệm vụ: {{mô tả}}. Input: {{...}}. Output kỳ vọng: {{...}}.
2. {{tên subagent 2}} — nhiệm vụ: {{mô tả}}. Phụ thuộc output của bước 1: {{có/không, cụ thể phần nào}}.
3. {{tên subagent 3}} — nhiệm vụ: {{mô tả}}.

Quy tắc điều phối:
- Nếu subagent trả về output không đạt tiêu chí {{tiêu chí cụ thể}}, yêu cầu chạy lại tối đa {{N}} lần trước khi báo lỗi cho tôi.
- Các bước {{X, Y}} có thể chạy song song vì không phụ thuộc nhau.
- Sau khi tất cả subagent hoàn tất, tổng hợp kết quả thành: {{định dạng output cuối cùng}}.

Báo cáo lại cho tôi: mỗi subagent đã làm gì, kết quả chính, và điểm nào cần tôi duyệt tay trước khi đi tiếp.
```

## Checklist
- [ ] Mỗi subagent chỉ có 1 trách nhiệm rõ ràng, không chồng lấn nhiệm vụ với subagent khác
- [ ] Đã xác định rõ phụ thuộc giữa các bước (bước nào phải chờ, bước nào chạy song song được)
- [ ] Orchestrator có tiêu chí cụ thể để đánh giá output subagent "đạt" hay "chưa đạt" (không chỉ dựa cảm tính)
- [ ] Có giới hạn số vòng lặp/số lần retry để tránh subagent chạy lặp vô hạn
- [ ] Đã test chạy toàn bộ pipeline với 1 case thật, xác nhận output cuối cùng dùng được ngay

## Expected Output
Một hệ thống gồm 1 file orchestrator (system prompt hoặc code điều phối) + N file định nghĩa subagent, chạy 1 lệnh ra kết quả tổng hợp cuối cùng, kèm log rõ ràng từng subagent đã làm gì và tại sao orchestrator chấp nhận/từ chối output đó.

## Common mistakes
- Orchestrator quá "mềm" — không có tiêu chí rõ để chấp nhận output subagent, dẫn đến pass-through cả kết quả sai xuống bước sau.
- Subagent chồng chéo trách nhiệm (2 subagent cùng làm 1 việc theo cách khác nhau) — gây mâu thuẫn kết quả, khó debug bước nào sai.
- Không giới hạn retry — 1 subagent bị lỗi cứ chạy lại vô hạn, đội quyền chi phí token mà không ai nhận ra (liên quan 06.03).
- Chạy tuần tự những bước lẽ ra chạy song song được — lãng phí thời gian không cần thiết cho task 1 người tự làm hết.
- Nhồi quá nhiều subagent (6-7 lớp) cho task thực ra chỉ cần 2-3 bước — over-engineer, khó bảo trì hơn 1 agent đơn giản.

## Phiên bản Claude Code
Đây là workflow dành riêng cho Claude Code — orchestration nhiều agent gần như không thực tế trong Claude Chat thông thường.

Cấu trúc project gợi ý:
```
project/
  .claude/
    agents/
      researcher.md       # subagent: research, tools: WebSearch, WebFetch, Read
      writer.md            # subagent: viết báo cáo, tools: Read, Write
      reviewer.md          # subagent: review chất lượng, tools: Read (read-only)
  CLAUDE.md                 # mô tả quy trình orchestrator cấp project
```

- Mỗi subagent là 1 file `.md` trong `.claude/agents/` với frontmatter `name`, `description`, `tools` — giới hạn tool tối thiểu cần thiết (reviewer không cần quyền `Write`).
- Trong phiên chat chính, đóng vai orchestrator: dùng Agent tool gọi từng subagent theo đúng thứ tự phụ thuộc, các bước độc lập gọi trong cùng 1 message (chạy song song thật sự — không phải giả lập tuần tự).
- Với pipeline chạy lặp lại định kỳ, cân nhắc viết script dùng Claude Agent SDK (Python/TypeScript) để tự động hoá toàn bộ chuỗi orchestrator → subagent mà không cần ngồi chat tay mỗi lần.
- Dùng `isolation: "worktree"` cho subagent nào sửa code, để tránh các subagent song song ghi đè file của nhau.
- Log lại kết quả mỗi subagent vào file riêng (vd `logs/researcher-output.md`) để dễ debug khi orchestrator ra quyết định sai.

## Khi nào nên dùng Deep Research
Cân nhắc dùng khi:
- Bạn chưa quyết được kiến trúc orchestration nào phù hợp (sequential vs parallel vs hierarchical) cho loại task cụ thể của mình, và cần tổng hợp best practice mới nhất từ nhiều nguồn (Anthropic docs, case study cộng đồng) trước khi thiết kế.
- Task có subagent cần tích hợp 1 API/công cụ bên ngoài lạ, cần research kỹ giới hạn (rate limit, cost, độ tin cậy) trước khi giao quyền cho subagent tự gọi.
Với việc thiết kế pipeline nội bộ đã rõ quy trình (như ví dụ trên), không cần Deep Research — viết trực tiếp theo checklist là đủ.
